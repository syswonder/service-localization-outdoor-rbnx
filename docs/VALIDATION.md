# 独立 Robonix 运行验证

2026-11-05。本次没有连接实机，没有改变原有 19865 网页演示，不实现 Scene 前端。

## 已通过

- G70 原语 10 项测试、WIT 原语 7 项、定位服务 8 项、导航服务 26 项，共 **51 项**。
- 真实 `rbnx build -f robonix_manifest.yaml` 构建五个包：虚拟输入、G70、WIT、定位、导航；不是只做 import。
- 真实 `rbnx boot` 拉起 **Atlas + Soma**；Soma 管理三个 primitive 的 INIT/ACTIVATE，rbnx 管理定位与导航 service 的生命周期，输入/输出能力通过 Atlas 发现与连接。
- G70 与 WIT 的真实原语驱动读取 **PTY 合成字节**（GGA/RMC/GST、0x51/0x52/0x53）；并非跳过原语直接给定位服务伪造 Odometry。
- 定位服务独立产生 Odometry/TF/状态，导航服务独立用 NavFn/DWB 执行 gRPC 提交的参考路线。
- 验证完成：到达并停车、取消、姿态帧断流时实测 gyro 仍可用于停车、故障后恢复及新的任务成功。最终虚拟速度为零。
- 正常停机后未发现本轮标记下需要最终强杀的残留进程。测试仍保留按唯一 run 标记清理的兜底，绝不按通用 ROS 进程名杀进程。

原始报告摘要与末态见 `validation/independent-stack.json`，源码指纹见 `validation/source-manifest.json`。

## 与旧仓库的边界

测试在新建容器中运行，只挂载两个原语仓、定位仓、导航仓和 Robonix SDK；不挂载旧 outdoorNav 工作区。运行代码没有导入 `outdoornav` 或 `outdoornav_ros`。

测试不需要原场景 bundle、地图生成器、旧 UDP 串口转发器或旧定位节点。map 原点、传感器安装和动态地图大小均显式放在部署配置中。原前端作为临时业务演示保持现状，不属于这条独立运行链；后续 Scene 只需消费定位与导航契约。

## 修复的接入问题

1. 模拟 primitive 启动不能假定框架总提供 `RBNX_PACKAGE_ROOT`；从启动脚本自身定位包根。
2. 所选框架使用命名空间 Driver；为既有两个原语提供兼容 manifest，新定位服务显式声明唯一一种 Driver，避免“注册成功但 INIT 从未执行”。
3. 独立 ROS 姿态与 gyro 的接收时间有轻微先后差，不能照搬旧 UDP“同一时刻”假设；保留原始时间，用既有 IMU 时间窗进行有界配对，不伪造时间戳。
4. 标准消息与 RTK 状态跨话题异步到达，按原语提供的 header 时间戳缓存配对，不能把不同测量当成同一帧；重复接收机 UTC 不刷新测量。
5. 初始化前的 HTTP 端口检查允许正常 TIME_WAIT 复用，但仍拒绝现有监听者，避免把“已关闭连接”误报成“已有服务”。

## 尚未验证的硬件条件

- G70 实机是否已输出 RMC/GST；没有则不会伪造速度或位置协方差，也不会自动修改设备设置。
- RMC 的地速不等于已经证明是多普勒；它没有速度精度字段。测试用的速度误差界限只针对虚拟输入，部署默认未确认。
- WIT 的实际安装旋转、北向修正、姿态精度，以及设备当前是否输出所需帧，仍需部署测量。
- 真实 NTRIP/RTCM 连接、串口权限、真实雷达、本体 TF 和底盘输出未在此轮验收。

这次通过的是“完全由 Robonix 管理、独立于旧仓的虚拟运行”，不是实机导航验收。
